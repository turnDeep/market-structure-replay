# クラウド定期更新の実装・確認記録

## 固定した範囲

GitHub Actionsで毎日09:00 Asia/Tokyoに更新する。NQ=F / NKD=F、v0.11の既存設定、初回の採用帯・売買履歴・実行クロックを維持する。ブローカー発注やパラメータ最適化は追加しない。
元のエンジン69 Pythonファイルを両銘柄に同梱。NKD版との差分はNQ=F→NKD=Fの文字列だけ。コード/ビューをバイトハッシュで固定し、改行変換も禁止する。

## 最新足の確定判定に関する訂正

初回ローカル更新では、直近17:00 Chicago境界により10月15日を完了日足としていた。しかし2026-10-16 01:48 UTCの再取得で、NQの10月15日Closeは保存値30051.25から30059.50、Volumeは26612から33131へ変化していた。NKDでも同日High/Close/Volumeの変化を確認した。
Yahooの`exchangeTimezoneName=America/New_York`、取引期間metadataもNY当日23:59までで、その時点はまだ10月15日。CME境界だけではYahoo日足ラベルの確定を保証できない。

対応：配信元の当日を必ず除外する境界も併用する。10月14日までを凍結し、すでに保存された10月15日は暫定表示に訂正する。次回、10月15日がこの厳しい境界を満たすときだけ、その暫定末尾を再取得・同設定再計算する。それ以前の履歴は遡及変更しない。元のファイル/コミットは残す。
この保守的方針では日本時間09:00の最新ラベルが1日以上遅れることがある。正規CMEセッション暦・清算価格の保証ではなく、後日のベンダー修正もあり得る。

## 検査

- 29件のユニット/AppTest：夏冬の確定境界、曖昧時刻拒否、現在NY日付除外、凍結コードと入力のハッシュ、シンボル限定アダプタ、不正OHLCV、HTML内JSON安全差し替え、無更新時に再計算しないこと、2銘柄目の取得・再計算失敗で何も公開しないこと、未約定SELLに架空の約定を作らないこと、携帯可能な更新後入力の読戻し、更新件数の再計算等。
- 実APIローカル取得：2026-10-16 01:50 UTC。NQ/NKDとも確定候補末尾10月14日、更新中10月15日を除外。空応答/API例外なし。新しい確定足なしでNO_NEW_COMPLETED_DATA、公開データは変更なし。
- 保存済みフルログに対する新しいポータブル出力アダプタの照合：既存6クエリの全行を保持し、売買ID/日付/価格/SL/損益と日次状態・帯・200SMAを確認。これはエンジンの新規再実行とは別。
- 表示モデル検査はNQ 26,766件、NKD 22,798件を実行。実ブラウザで両銘柄のチャート、定期更新表示、暫定警告、更新履歴リンク、訂正済みフッターを確認。説明文だけを再ビルドし、全クエリ行・アプリID・表示構成は保持した。
- GitHub Linux上の全履歴回帰検査：結果はActions実行履歴を参照。最後の実データを前日までの入力から再計算し、過去の約定と固定設定、全表示行の保持を確認する。verifyはデータ公開しない。初期末尾自体は暫定であり、この再現検査は確定性や予測優位性を証明しない。

## 保存・公開ゲート

取得→不正値検査→隔離プロセスで再計算→凍結入力/設定/約定照合→表示用JSON作成→既存行照合→JSモデルのas-of/損益/SMA検査→pytest→単一通常コミット/push。
どこかで失敗したらリモートの公開世代は不変。過去のベンダー修正は記録し未適用。2銘柄の一方が失敗しても部分公開しない。push競合も自動force/mergeしない。
新しいNQ FVG再テストなど既存ビューが正確に表現できない経路は安全停止する。更新の成功と戦略の予測優位性は別で、NOT_VALIDATEDを維持する。

## 運用の境界

Actions利用枠・GitHub/Yahoo障害・仕様変更・権限制限により停止や遅延が起こり得る。開始時刻のSLAはない。失敗の詳細と検査レポートはGitHub Actionsに残る。Streamlitの認証設定/公開アプリURLはこの検査とは別である。
